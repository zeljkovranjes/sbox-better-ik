# Decisions

Log of judgment calls made where the spec was silent, with reasoning. Newest entries at the bottom.

| Date | Decision | Reasoning |
|------|----------|-----------|
| 2026-07-15 | Ident `better_ik`, Org `notpointless`, matching sibling projects (humanoid-retargeter, monster-ai, the_director_ai, two_brains_ai) | Consistency with the author's existing s&box package namespace. |
| 2026-07-15 | Engine-agnostic solver math lives in `Code/BetterIk/Maths/`, using `System.Numerics.Vector3`/`Quaternion` with namespace-scoped aliases (not Sandbox's global `Vector3`/`Rotation`) | Mirrors the proven pattern in humanoid-retargeter: lets the same source compile both inside the s&box editor and in a plain net8.0 `dev/BetterIk.Dev.csproj`, so the analytic solver and pole vector math are unit-testable (xunit) with no editor running at all. This is the only way to get truly autonomous, no-human-in-the-loop testing for the core geometry, since the s&box MCP server requires a live editor process. |
| 2026-07-15 | `TwoBoneIK` component itself (and any `DrawGizmos` override) lives in `Code/`, not `Editor/` | It is a runtime component meant to ship in the built game, not an editor-only tool. `Component.DrawGizmos` is available outside the `Editor/` assembly and only draws while selected in-editor. `Editor/` is reserved for actual editor-only tooling (custom inspector widgets, etc.) added in a later stage if needed. |
| 2026-07-15 | Solver is a pure static function (`TwoBoneIkSolver.Solve(in TwoBoneIkInput) -> TwoBoneIkResult`) over plain structs, operating on positions/rotations in one common space | No state means lerp-safe by construction, thread-safe, allocation-free, and trivially unit-testable; the input struct documents the entire per-frame contract. |
| 2026-07-15 | Root/mid outputs are delta rotations composed onto the animated world rotations, built as frame-to-frame maps (bone direction + bend-plane normal), never shortest-arc vector-to-vector | Deltas mean the solver never reads any bone's local axes (satisfies "no axis convention" requirement) and preserves animated character; the frame map pins twist, eliminating 180-degree shortest-arc roll flips that would fail the orbit continuity test. |
| 2026-07-15 | Bend axis derived from the current animated pose (`cross(end-root, mid-root)`), with fallback ladder: bind-pose normal from `AnalyzeBindPose`, then deterministic arbitrary perpendicular | Current pose is the best per-frame hinge estimate and needs no rig convention; the ladder guarantees a defined solve even for perfectly straight chains. |
| 2026-07-15 | Default pole = bind-pose elbow offset direction (mid joint's perpendicular offset from the root-end line), with `IsReliable=false` flag when the bind chain is collinear | Production rigs pre-bend elbows backward and knees forward in bind pose, so the rig itself encodes the anatomically correct pole with zero convention assumptions; the flag lets the later component stage warn or apply a heuristic for perfectly straight rigs. |
| 2026-07-15 | Pole passed to the core as a root-relative direction vector (magnitude ignored), not a world position | The math only uses the component perpendicular to the root-target axis, so direction is the minimal sufficient input; it serves both the pole-GameObject path (position minus root) and the default-pole path (rotated bind direction) with one code path. |
| 2026-07-15 | Master weight multiplies position and rotation weights inside the core (`wPos = master*pos`, `wRot = master*rot`) | Keeps the documented blending semantics in tested engine-agnostic code instead of re-implementing it per engine layer. |
| 2026-07-15 | Weight blending is done by slerping the delta rotations toward identity and recomputing positions via FK, never by lerping positions directly | Straight-line position lerp squashes bone lengths mid-blend (visible popping); rotation-space blending preserves lengths at every intermediate weight, which the tests pin. |
| 2026-07-15 | Soft-IK uses the exponential falloff `dEff = dSoft + R(1 - e^-((d-dSoft)/R))` with `dSoft = (1-SoftFraction)*Lmax`, `R = SoftFraction*Lmax`; stretch is a uniform bone scale `s = clamp(d/dEff, 1, 1+MaxStretch)` | Industry-standard soft-IK (Softimage-style) is C1-continuous at onset and asymptotic at max reach, killing full-extension jitter; coupling stretch to `d/dEff` gives gradual stretch onset when soft is enabled. |
| 2026-07-15 | Angles are radians in the math core; degree conversion happens at the component layer | System.Numerics is radians-native; converting at the engine boundary keeps the core dependency-free and unambiguous. |
| 2026-07-15 | Degenerate chain (near-zero bone length) returns pose passthrough with `Solved=false`, but end rotation still blends toward the target rotation | Rotation goal is independent of chain geometry, so it should keep working; the flag lets the component warn once instead of spamming or throwing. |
| 2026-07-15 | Continuity is NOT required through genuine singularities (target exactly at root, pole exactly on the root-target axis); NaN-freedom and bounded output ARE required everywhere | These are true mathematical singularities where any pure stateless function must jump; requiring boundedness plus the degeneracy ladders gives the strongest guarantee a stateless solver can honestly make. |
| 2026-07-15 | All geometric epsilons are relative to total chain length (`Lmax`), defined as named constants | Absolute epsilons break on very small or very large rigs; the scale-equivariance test enforces this. |
| 2026-07-15 | Added a near-side reach clamp: `dFinal` is clamped up to at least `\|l1s - l2s\|` (mirroring the existing far-side clamp at `Lmax`) | Found by the seeded fuzz test (iteration 12, unequal bone lengths, target inside the dead zone): the original spec's edge-case table only covered "beyond max reach" and "exactly at zero," missing that unequal-length chains also have a minimum reach `\|l1-l2\|` below which the target is geometrically unreachable (folding the longer bone back over the shorter one is as close as the chain gets). Without the clamp, `cosAlpha` fell outside [-1,1] by a large margin, and clamping only the angle (not the distance) left `midSolved`/`endSolved` mutually inconsistent (not exactly `l2` apart), so the FK-reconstructed end position drifted off target by up to ~0.16 units in the fuzz run. This is a deviation from the literal spec text and is flagged to the Advisor for review, not a silent fix. |
| 2026-07-15 | Advisor sign-off on near-side dead zone clamp: approved as implemented (`dFinal = max(dFinal, \|l1s-l2s\|)`), no new result flag added; `Solved` remains `true` and the clamp stays silent, exactly symmetric with the existing silent far-side over-reach clamp | Verified algebraically that clamping to `\|l1s-l2s\|` drives `cosAlpha` to exactly `1` (or `-1`), so `alpha` lands at the true fully-folded geometry rather than an arbitrary clamped angle — the fix is geometrically exact, not an approximation. `Solved=false` is reserved for chains that cannot be solved at all (near-zero bone length); a clamped-but-otherwise-valid reach on either side of the `[\|l1-l2\|, Lmax]` interval is a normal, expected outcome of two-bone geometry (e.g. human forearm != upper-arm length) and both directions already silently clamp per the original Section 5 spec, so adding a flag for only one side would be an asymmetric special case. A future component/editor layer can still detect and warn about this itself (by comparing target distance to `\|l1-l2\|`/`Lmax` using the same `AnalyzeBindPose` lengths) without any new field on `TwoBoneIkResult`; deferred rather than speculatively added now. |
| 2026-07-15 | Advisor sign-off on `SelectElbowDirection` fallback ladder step 3: implemented as `cross(input.FallbackBendNormal, aHat)` directly, without a separate pre-orthonormalization of `FallbackBendNormal` against `aHat` | Confirmed equivalent to the spec's "orthonormalized" wording: crossing any vector with a unit axis already annihilates the component parallel to that axis, so the result is perpendicular to `aHat` regardless of whether `FallbackBendNormal` was pre-projected. The spec's phrasing described the required geometric property (perpendicularity), not a mandated extra step; the simpler implementation is correct and slightly cheaper. No change requested. |
